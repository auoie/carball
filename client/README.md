# Web client

Browser freeplay: Three.js rendering on top of the WebAssembly physics engine (`engine/`), in the
arena we generated (`out/arena/`). TypeScript (strict) + Vite.

## Run
```sh
# 1. Build the engine for the web (once, and after engine changes); see engine/README.md
PATH=/usr/lib/emscripten:$PATH emcmake cmake -S engine -B engine/build-wasm -DCMAKE_BUILD_TYPE=Release
PATH=/usr/lib/emscripten:$PATH emmake make -C engine/build-wasm -j

# 2. The client
cd client
npm install
npm run dev          # http://localhost:5173
npm run build        # production build in dist/ (typechecks first)
```

## Correctness checks
```sh
npm run check        # tsc (3 projects) + ESLint (strict type-aware) + Vitest
npm run build && npm run e2e   # Playwright in the installed Chrome: load, drive, ball cam, reset
```
- **TypeScript** (`tsconfig.app.json`): `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, no unused
  code, no implicit returns or fallthrough. Tests (`tsconfig.test.json`) and config/e2e files (`tsconfig.node.json`) are
  separate projects, so Node APIs can't leak into browser code.
- **ESLint**: `typescript-eslint` `strictTypeChecked` + `stylisticTypeChecked`, exhaustive switches, no `any`; zero warnings allowed.
- **Engine types**: `engine/build-wasm/rlengine*.d.mts` are generated by Emscripten from the C++ bindings, so the
  client is type-checked against the real engine API.
- **Vitest**: pure modules (input mapping, deadzones, fixed-step clock, camera maths, coordinate conversion) plus
  an integration test of the engine wrapper against the real WebAssembly module (`src/engine/world.test.ts`).

## Layout
| Path | |
|---|---|
| `src/engine/world.ts` | typed wrapper around the engine (`World`: cars, ball, pads, events, snapshots) |
| `src/engine/cmf.ts` | reads the arena collision mesh (also used for rendering) |
| `src/input/` | bindings from Rocket League's `DefaultInput.ini`, deadzones, keyboard/mouse/gamepad → controls |
| `src/loop/fixedStep.ts` | physics at a fixed 120 Hz; rendering interpolates between ticks |
| `src/camera/` | the game's car cam, ball cam and transitions, ported from its UnrealScript (`notes/camera.md`) |
| `src/render/` | Three.js scene; placeholder car (hitbox + wheels), ball, pads, arena |
| `src/game/freeplay.ts` | freeplay rules: goals, ball reset, kickoff reset, ball-in-front / ball-on-car |

Coordinates: the game's frame (x, y horizontal, z up, left-handed) maps to Three.js as `(x, z, y)`
(`src/render/coords.ts`). Blue defends −y, orange +y.

## Controls
H in game shows them. Defaults follow the game: W/S throttle (and pitch in the air), A/D steer/yaw,
Q/E air roll, right mouse jump, left mouse boost, Left Shift powerslide/air roll, Space ball cam,
Backspace reset, 1/2 ball in front / on car. Gamepad: RT/LT, left stick, A jump, B boost, X powerslide/air roll,
Y ball cam, RB reset, D-pad down/up.
